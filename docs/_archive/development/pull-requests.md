# Development — Pull Requests

> Describes pull request standards — what every PR must contain.

---

## Pull requests must be human-readable

A PR is never just "Fixes LP-142". Every PR created through the Launchpad workflow carries:

| Section | Content |
|---|---|
| What Changed? | Plain-English summary of the implementation |
| Why? | The product reason, referencing the Decision Doc |
| User Impact | What changes from the user's perspective |
| Implementation Summary | Concise technical overview |
| Key Decisions | Implementation decisions made during the work — material ones are promoted into the Decision Doc, not left buried in the PR |
| Testing | How the work was verified |
| Related Work | Linear ticket, Decision Doc, dependencies, related PRs |

*Source: architecture decision review, confirmed 2026-09-02.*
